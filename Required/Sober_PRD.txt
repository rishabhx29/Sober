1. Executive Summary
Sober is a deep-system Android application built on a single honest premise: smartphone addiction is real, and willpower alone doesn't beat it. Sober gives users complete, unbypassable control over their digital habits — hard app-usage limits, focus session locking, in-app content section filtering, and intelligent scheduling — all in one calm, minimal interface. Unlike existing screen-time tools that can be circumvented in seconds through Settings, Sober uses Android's Device Administration, Accessibility, and VPN service layers to stay active even when the user tries to force-stop or uninstall it during an active block.

The name is intentional. "Stay Sober" reframes phone use the same way sobriety reframes drinking — not as a failure of character, but as something that requires a system. Sober is that system. Once a rule is in place, it stays in place, even if the user changes their mind in a moment of weakness.

1.1 Key Goals
Block entire apps when daily time limits are reached — hard lock, no tap-to-dismiss dialog
Lock the phone into a Focus Session for a set duration with no easy exit
Block specific sections inside apps (Instagram Reels, YouTube Shorts, Explore, TikTok FYP)
Run as a persistent background service that survives app removal from recents and phone reboots
Show clear, honest usage data — no sugarcoating how much time is actually being lost
Stay out of the way when not blocking — a minimal UI that never becomes its own distraction

1.2 Platform Decision
Sober is built natively for Android first because Android's open permission model exposes the system APIs needed for deep blocking: UsageStatsManager, AccessibilityService, DevicePolicyManager, and VpnService. These APIs simply do not exist on iOS due to sandbox restrictions. An iOS Phase 2 using Apple's Screen Time framework is planned but will have reduced enforcement power.


2. Problem Statement
The average smartphone user spends 4–6 hours per day on their device. A significant portion goes toward passive, algorithmically-driven consumption — Reels, Shorts, TikTok feeds — designed specifically to make you stay longer than you intended. The user knows this. They set a limit. Then they ignore it. The willpower-only approach fails consistently and predictably because:

Every existing screen-time tool (Digital Wellbeing, Screen Time) can be disabled in Settings in under 10 seconds
Limits surface a dialog the user can tap "Ignore for today" on — one tap and the rule is gone
There is no way to block specific sections of apps without blocking the entire app — users won't block Instagram entirely because they need DMs
Focus timers don't survive being swiped away from the Recents screen
There is no single honest view of where time is actually going — Digital Wellbeing buries the data

Sober solves all five of these at the system level. The rules you set stay set.

4. Feature Specifications
4.1 App Usage Limits
The foundational feature. Users set a daily time budget per app. When the budget is exhausted, Sober overlays a full-screen block that cannot be dismissed until midnight (reset time).

4.1.1 Overall Daily Screen Time Limit
User sets a total daily phone usage cap (e.g., 3 hours)
A persistent notification shows remaining time
At 80% usage a gentle warning notification fires
At 100% usage, Sober launches an overlay over every app opened (cannot be dismissed)
The overlay shows: time remaining until midnight reset, a motivational message, and a "cooldown" progress ring

4.1.2 Per-App Daily Time Limits
User can set individual limits for each installed app
Example: Instagram → 30 min/day, YouTube → 1 hour/day
When the per-app limit is hit, that specific app is blocked (overlay appears when user tries to open it)
Other apps remain accessible
Per-app limit is independent of the overall screen time limit — either one can trigger a block

4.1.3 Block Overlay
Overlay Screen Contents:
App icon + name with a red lock icon badge
Message: "You've used your [app name] time for today."
Remaining time until midnight reset (countdown ring)
Optional motivational quote (rotates daily)
Emergency override button (see Anti-Circumvention section for delay logic)

4.2 Focus Sessions
A Focus Session is a time-boxed lock where the user commits to avoiding distractions for a set duration. During a Focus Session, the user cannot open blocked apps, cannot receive notifications from those apps, and the session cannot be cancelled without a significant cooldown penalty.

4.2.1 Session Configuration
Duration: 15 min, 25 min (Pomodoro), 30 min, 45 min, 1 hour, 90 min, 2 hours, Custom
App blocklist: user selects which apps are blocked for this session
Notification silencing: silence all / silence selected apps / silence all except calls
Session label: "Study", "Work", "Gym", "Reading" (custom labels too)

4.2.2 Session Runtime Behavior
Foreground Service starts immediately — persists even when app is removed from Recents
Persistent notification (cannot be swiped away) with a countdown timer is shown
When user opens a blocked app → instant overlay with session timer countdown
Notification from blocked apps are intercepted by NotificationListenerService and suppressed
If the user tries to disable Accessibility/Notification access, Sober detects this and warns

4.2.3 Focus Mode (Light Version)
Focus Mode is a non-timed variant of Focus Session — it stays active indefinitely until manually turned off. Useful for "I want to focus right now with no timer." Disabling Focus Mode requires no cooldown.

4.2.4 Session Completion
When timer ends, a celebration screen appears: session duration, apps avoided, streak update
Option to immediately start another session
Session logged to history for stats

4.2.5 Cancellation & Penalty System
To prevent impulsive cancellation:
Cancel button requires 5-second hold (no accidental taps)
After hold, a 60-second "regret timer" starts — user can revert during this window
If cancelled, the cancelled session is marked in history with a broken streak indicator
Three cancellations in one day triggers a "Streak Warning" notification

4.3 In-App Content Section Blocking
This is Sober's most unique feature. Rather than blocking entire apps, it blocks specific addictive sections within apps while leaving the useful parts accessible.

4.3.1 How It Works (Technical)
Sober's AccessibilityService monitors active app packages and Activity/window labels in real time. When the user navigates to a blocked section (detected by activity class name, content description, or UI node resource IDs), the service launches a transparent overlay window blocking interaction.

4.3.2 Supported Apps & Blocked Sections — v1.0


4.3.3 Block Overlay for Sections
Semi-transparent blur overlay covers the blocked section
Shows section name, lock icon, and a brief reason ("Reels is blocked — you set this rule")
Back button to return to a safe section of the app
Not dismissible unless user goes to Sober settings and disables the rule

4.3.4 Custom Block Rules (Advanced)
User can create custom rules using keyword matching in notification content
User can block any specific app package name entirely

4.6 Anti-Circumvention System
This is what separates Sober from ordinary screen-time tools. Every vector by which a user could bypass their own rules is closed off.

4.6.1 Device Administration
Sober requests Device Administrator privileges on first launch
With Device Admin, Sober cannot be uninstalled without first revoking admin — which requires opening Sober settings
During an active Focus Session, Sober's settings are PIN-locked

4.6.2 Accessibility Service Persistence
If the user navigates to Settings → Accessibility and tries to disable Sober, the app detects this and immediately re-opens the Accessibility settings toggle
This behavior is disabled when no Focus Session or hard limit block is active

4.6.3 Foreground Service (Survives Recents Clear)
Sober runs a persistent 
[object Object] with a non-dismissible notification
Service restarts automatically via a broadcast receiver if killed by the system
Registered for BOOT_COMPLETED to restart after phone reboot

4.6.4 Emergency Override
An emergency override exists but is intentionally difficult:
Hold override button for 10 seconds
Enter PIN + solve a simple math problem (prevents reflexive override)
A 5-minute wait timer starts
After 5 minutes, the block lifts for 15 minutes only
Override usage is logged in stats with a visual flag (you can't hide that you broke the rule)

4.6.5 VPN-Based Content Blocking (Phase 2)
Sober sets up a local VPN tunnel (no internet traffic leaves device) to intercept DNS requests
Blocked app domains are resolved to a local null IP, preventing network access
This provides a second layer of blocking that works even if Accessibility Service is somehow disabled

5.1 High-Level Architecture Overview

5.2 Service Architecture

SoberCoreService (ForegroundService)
The heart of the app — runs at all times
Polls UsageStatsManager every 30 seconds to check current app usage against limits
Communicates with AccessibilityService to trigger overlays
Manages Focus Session timer via CountDownTimer backed by saved state
Handles midnight resets (resets usage counters in Room DB)

SoberAccessibilityService (AccessibilityService)
Listens for window state change events and content change events
Checks foreground app package against blocked app list
For in-app section blocking: inspects UI node tree to find blocked section indicators
Launches overlay Activity when blocked section is detected
Detects Settings → Accessibility screen and handles re-protection logic

SoberNotificationService (NotificationListenerService)
Intercepts all incoming notifications
During active Focus Session, cancels notifications from apps on the blocklist
During non-session hours, allows all notifications through

SoberBootReceiver (BroadcastReceiver)
Registered for ACTION_BOOT_COMPLETED
On boot, restarts SoberCoreService and re-applies all active blocks

7. Design System
Sober uses the Manuscript visual theme — a light-dominant, editorially-restrained design language inspired by quality paper planners and analog notebooks. Every colour appears for a functional reason. There are no gradients, no glows, no decorative shadows. The result feels like a tool you trust, not an app trying to impress you.

7.1 Visual Identity

7.1.1 Colour Palette — Manuscript


Colour discipline: Signal red (#C0392B) appears in at most one place per screen at any time. Its rarity is what gives it weight — when a user sees it, they immediately know something is blocked or at its limit.

7.1.2 Typography


Section labels (e.g. "TODAY'S APPS") use Label Small in all-caps with +1sp letter-spacing, sitting directly on the cream background with no card behind them — like chapter headings in a printed document.

7.1.3 Spacing & Shape System
Base unit: 4dp — every margin, padding, and gap is a multiple of 4
Corner radii: 4dp (filter chips), 14dp (cards), 16dp (bottom sheets), 28dp (pill buttons)
Card border: 1px solid #E8E0D5 — no shadow in default state
Pressed state: card border darkens to #C8BFB4, background dims to #F0EBE3
Button: solid navy #1A1A2E fill, white label, 28dp radius, 52dp height, no border
Outlined button: 1px navy border, transparent fill, navy label
Minimum touch target: 48×48dp (Material 3 spec)
Content gutters: 20dp horizontal padding on all screens

7.1.4 Iconography
Icon library: Material Symbols — Outlined weight for unselected, Filled for selected/active
Icon size: 22dp in nav bar, 20dp in list rows, 24dp in headings
Colour: navy #1A1A2E when active, muted #9C9490 when inactive, red #C0392B on block states
Block overlay: lock icon with no badge — red tint on the entire icon, not a separate badge
Streak icon: outlined flame, navy fill — never animated unless session just completed
App icons in lists: loaded via PackageManager, displayed at 36dp with 8dp corner clip

7.2 Navigation Structure

Sober uses a bottom navigation bar with 4 tabs. All top-level destinations are reachable in one tap from anywhere.


Bottom nav bar: white #FFFFFF, 1px top border #E8E0D5. Icons are thin-stroke Material Symbols. Selected: icon turns solid navy, label turns navy 11sp medium. Unselected: icon and label both muted gray #9C9490. No background pill or indicator bar — just the colour change. This keeps the nav bar invisible until you need it.

Settings is accessed via a gear icon in the top-right of the Home screen only — not a tab. Five destinations, four tabs.
